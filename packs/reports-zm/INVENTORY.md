# Zambia v1 reporting database: inventory

Zambia sent the script of its v1 reporting database (`OpenLDRReporting`) on 2026-10-09:
`corlix/fixtures/Zambia_views/script.sql` (UTF-16, 17,730 lines). This file says what happens to
each of its 181 objects in this pack. It was built on 2026-10-09 by reading every object.

How to read it:

- **Port**: the object is a report. It becomes a CE custom query. The query matches v1's output, not
  its SQL.
- **Merge**: the object is a copy of a ported report that differs by a constant (a province, a lab,
  a test type, a date window). It becomes a parameter of that report's query.
- **Absorb**: a helper (a function, a thin view, or a procedure that fills one of Zambia's copy
  tables such as `hivvl`, `tnd`, `eid`, `tbgnx`). Its logic is rebuilt inside the queries that use it.
  CE keeps no copy tables.
- **Blocked**: a report CE cannot produce, because CE does not hold the data it needs.
- **Drop**: not a report. A one-off extract (fixed years, a person's or project's name), a procedure
  that changes data, or something that is not lab data (help desk, HL7 message logs).

The `Purpose`, `CE data` and `Reason` cells cite line numbers in each object's own text. To read an
object, convert the script (`iconv -f UTF-16 -t UTF-8`) and search for its name.
